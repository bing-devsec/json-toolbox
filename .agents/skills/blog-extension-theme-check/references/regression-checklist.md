# 已遇到的主题问题对照表

本表提炼实际回归场景。当前路径和类名是排查入口，重构后先核实；“已确定的产品选择”用于避免倒退，不是其他主题的颜色模板。

## 历史现象 → 检查方式

| 区域 | 实际遇到的问题 | 其他主题应如何核查 |
| --- | --- | --- |
| 按钮与图标 | 转移按钮棕色底、蓝色箭头混用；各功能颜色缺少角色规范 | 格式化/确认、转换/上传/转移、复制/下载、清空/删除是否按主要、普通、危险等角色一致配色；SVG 是否继承文字色；正常、交互、禁用状态是否成套 |
| 顶部导航 | 新主题多出默认主题没有的粗横线，内外容器重复绘制边界 | 比较共同高度、内边距和边线来源，避免主题意外改变结构；不要仅为一种材质叠加额外粗边 |
| 主按钮组 | “对比”和嵌套的“数据转换”之间边界消失 | 检查相邻按钮、嵌套 dropdown、首尾圆角与合并边框；浅深模式均需清楚，不沿用实色按钮组的白色 divider |
| 层级折叠组合控件 | 下拉与折叠像两个独立组件，存在凹凸、双重边框；点击后整个控件出现粗外圈；中线过强或完全无区分 | 同一外框与底色下区分选择区和执行区；检查圆角、接缝、hover、禁用和键盘焦点。需要分隔时可用低对比短细线；不要改变控件宽度或折叠交互 |
| 设置弹窗 | 深色模式头尾出现白色横边，局部区域仍使用浅色默认样式 | 检查 header/body/footer、关闭按钮、accordion 及卡片的背景/边界；展开、收起和重开后都要检查 |
| 菜单功能选项布局 | 5 个勾选项未铺满内容宽度，尾部留白大；下行对齐关系不清楚 | 目前产品选择为每行最多 5 个、首尾对齐内容区、列间均匀、下行按列对齐。较窄面板适当减列；核对英文长标签及复选框默认 margin |
| 脱敏字段候选 | 弹层背景已变暗，字段名仍是固定深灰色，几乎不可见 | 用数组样例打开候选项，检查路径名、右侧数量/类型、悬停和键盘高亮；不能只检查输入框本身或 li 的继承色 |
| 脱敏功能说明 | 展开后四个小标题仍蓝色，正文偏蓝灰；局部示例曾依赖行内白底 | 展开全部规则，区分规则标题、正文、辅助示例、code 背景/边界/前景、左侧强调线及展开按钮。追踪旧的后代 p、first-child/last-child 与 !important 覆盖 |
| Monaco 行号区 | 纸感深色下行号底色与正文相同，空编辑器分区消失 | 核对 gutter 与正文底色、必要的细边线、普通/当前行号和折叠箭头；空白、多行、编辑/预览/Diff 都查看。Monaco editorGutter.background 与 CSS .margin 覆盖需一致 |
| Diff 中间同步面板 | 行号已适配，中间整条同步区域仍是固定蓝灰色 | 检查 .diff-cell-center 的头部、正文及底部，背景、两侧边线、同步箭头的普通/hover/active。空白和有差异两种状态都打开，不把差异数据本身的红/蓝高亮当作外观遗漏 |
| 排序参数弹窗 | “排序方向”提示卡仍白底；“排序范围”“排序字段”标题深灰难辨 | 检查方向卡片、表单标签/说明、自动补全及 footer；标题不能比辅助说明更难辨认 |
| 排序演示浮层 | 演示仍用独立的黑灰皮肤，与纸感界面不一致 | 打开演示，逐项查看 Popover、箭头伪元素、标题栏、正文、当前设置卡片、参数 code、底部及关闭按钮；不能只调整弹层外壳 |
| 演示主要操作 | “执行排序”与“上一步”都是普通描边，主次不清；通过比较回调身份判断样式不可靠 | SortDemoStep 显式声明按钮角色；开始、设置参数、执行、继续、结束应明确主要操作，上一步/重试保留普通层级。检查不同步骤不是只看开始页 |
| 演示目标与进度 | 目标区域仍有亮蓝色脉冲框，进度圆点仍用另一套灰色 | 检查高亮动画的每个关键帧、外圈透明色、活动/未活动圆点；强调色跟随目标主题，关闭演示后清除高亮与浮层 |
| 局部完成但整体验收遗漏 | 一次只看父容器、行号或某个步骤，遗漏中间面板及深层内容 | 修改共享变量后重新打开受影响的二级入口：下拉、说明、演示、Diff。记录具体检查项，未覆盖的项不得默认为通过 |

## 排查入口

- 颜色和传播：src/themes/interfaceThemes.ts、paperTokens.ts、ideTokens.ts、useInterfaceTheme.ts、interfaceThemes.css、paperControls.css、ideControls.css；同时检查注册表 controlSystem 与 body 的 data-theme-controls 是否一致。新主题采用自己的语义色；不要把 paperControls.css 当作全局覆盖层。
- 工具栏/设置：src/components/JsonToolWorkbench.vue、SettingsDialog.vue、AppearanceSettings.vue、settingsLayout.css。
- 脱敏：src/components/DataMaskingDialog.vue；重点搜索 path-help、path-rule-heading、path-rule-example、path-text、field-path-autocomplete。
- 排序与演示：src/components/JsonSortFeature.vue、composables/useJsonSort.ts；重点搜索 SortDemoStep、demo-guide-popover、demo-current-settings、demo-highlight-target、demoPulse、step-dot。
- 编辑器与 Diff：src/components/utils/monacoThemes.ts、JsonToolDiffPane.vue；重点搜索 editorGutter.background、.margin、diff-center、diff-sync-btn。

先用 rg 搜索实际来源，再检查浏览器计算样式。硬编码颜色不一定是错误，可能是默认主题回退值或数据语义；确认它是否在目标主题下仍实际生效。

## 当前已经认可的结构，避免主题工作顺带倒退

- 保留设置卡片；主题设置可折叠，工具栏功能并入通用设置，编辑器设置单独分组。
- 语言在通用设置中；浏览器插件已移除原悬浮的语言/明暗切换组件，不通过主题任务恢复它。
- 编辑器设置标题下已去掉“调整文字显示、语法检查和滚动方式。”这句说明，不通过复制旧组件重新引入。
- 纸感层级组合控件当前使用统一外框＋低对比短细线，鼠标点击无额外粗外圈；其他主题可有自己的材质，不要求照抄纸感的尺寸和颜色。

## 最小复现场景与验证强度

1. 脱敏候选：输入 {"CIS":[1,2],"DB3":[3,4]}，打开脱敏并聚焦空字段路径；检查两个候选和数量，按方向键高亮并实际选择。再展开规则说明，检查四种匹配规则。
2. 字段排序：在排序设置选择按字段值排序，输入 [{"id":2},{"id":1}]，打开排序；检查方向卡片、标签、字段候选和主要按钮。
3. 排序演示：从“演示示例”进入开始、参数、执行、结果这几类界面。若改动按钮角色或步骤数据，覆盖全部受影响步骤；整体验收时可走完整的 Array、嵌套 education、Map id、Map value.score 演示。仅修改同一颜色变量不要求每次重跑所有步骤。
4. 编辑器与 Diff：空编辑器、多行嵌套 JSON、空 Diff、左右 {"a":1} 与 {"a":2} 的有差异 Diff；观察行号边界、同步面板和箭头。涉及几何或交互时再补查折叠、滚动、同步操作。
5. 对应场景分别检查浅色和深色。只有影响性能、Worker 或解析链路时才追加大文件验证；通过小样例不能宣称已验证百万行性能。
