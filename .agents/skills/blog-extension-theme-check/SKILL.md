# 浏览器扩展主题核查（临时）

来自 2026-10-30 纸感主题开发中实际出现的问题，用于其他扩展主题开发时逐项对照。它是一份阶段性回归清单，不代表其他主题也必须采用纸感配色、分隔线尺寸或材质。

## 任务边界

- 仅作用于本扩展。开发边界和运行方式沿用本仓库 AGENTS.md 与 blog-extension；不要扩展到网页、后端或商店发布。
- 新主题开发或整体验收时读取完整的[历史问题对照表](references/regression-checklist.md)；局部修复时只检查受影响项及共享样式的相邻场景。核查请求先报告可复现问题；修复请求在已授权范围内处理。
- 先确认本次目标主题、明暗模式、当前未提交改动与实际运行页面。历史问题只提供线索，不假定其他主题一定有同样缺陷。

## 先确定语义，再调颜色

1. 对照目标主题自己的调色板，区分正文、说明、强调色、普通/主要/危险操作、底色、边界、选中和禁用状态。明暗模式分别设计，不能只把背景改黑。图标通常继承所在控件前景色。
2. 追踪完整覆盖链：调色板变量 → 根容器/body → 组件 scoped CSS → 旧暗色覆盖 → 行内样式 → Teleport 浮层 → Monaco 注册色及 DOM 覆盖。父容器颜色正确不代表子节点、伪元素或动画正确。
3. 优先补齐语义变量并收敛旧的固定色覆盖，避免靠越来越多的 !important 或主题排除条件遮盖冲突。保留默认 Element Plus 及其他主题已认可的表现。
4. 不把“非主题色”一概当成错误。JSON 语法、Diff 新增/删除、错误与成功反馈有自己的数据语义；重点检查遗漏的界面底色、文字、边线和交互强调。

## 结构与交互不能随主题退化

- 按钮组边界、层级选择＋折叠的组合关系、设置卡片和共同导航结构保持清楚。分隔线强度和留白按目标主题决定，不复制纸感主题的具体像素数。
- 保留键盘可见焦点。纸感主题已去掉鼠标点击层级选择器时包围整个组合控件的粗外圈，这不等于所有主题都禁用 focus-visible。
- 普通/hover/active/selected/disabled/focus-visible 都要考虑。禁用控件不应误用活跃强调色，主要操作应有明确角色；不要通过函数身份或中文按钮文案推断角色。
- 改 Monaco 配色时保持模型、撤销历史、行号宽度、折叠箭头与点击范围。材质效果放在静态外壳，不给滚动编辑区增加大面积模糊或重绘。

## 浏览器核查与交付

- 复用已有、可确认用途的预览；切换模式并实际打开目标弹窗、下拉和折叠说明。在自己的临时页面使用合成样例，不覆盖用户编辑内容。
- 从正常、空白/禁用和有数据状态中选取相关场景。整体验收覆盖浅色和深色；长路径、中英文长文案和较窄面板在影响布局时补查。通过真实选择/执行操作确认样式没有遮挡、裁切或破坏交互。
- 检查实际渲染的文字/背景对比度：可用正文通常以 4.5:1 为目标，必要的控件边界及焦点提示以 3:1 为目标；纯装饰细线、区域底色差和禁用文字不机械套用同一门槛。
- 保存能看见目标及周边关系的截图；等入场、展开动画结束，避免把半透明过渡帧当成最终效果。无法用浏览器确认时，明确记录未验证，不能用构建成功代替视觉验收。
- 代码修改后运行 npm run build；按影响运行现有相关测试。只有新的可观察行为风险才增加回归测试，不为颜色或 CSS 字面量编写镜像测试，不因局部外观修改固定要求百万行测试或全量演示。
- 报告目标主题/模式、复现步骤、根因、修复与验证；对照项区分“通过 / 有问题 / 未验证 / 不适用”，附原因。遵守现有资源收尾约定，保留待验收预览。

## 临时性质

后续其他主题完成核查后，可由用户决定把验证过的共性要求收敛进 src/themes/README.md 或稳定开发 Skill，再移除本临时 Skill。没有自动失效或删除期限。移除时同步检查本仓库 AGENTS.md、blog-extension/SKILL.md 及上层工作区的发现链接，避免留下失效入口。
