# JSON 工具箱浏览器插件

独立的 Vue 3 + TypeScript + Vite 项目，使用 Chrome Manifest V3。普通页面点击插件图标会打开完整的 JSON 编辑器；在 JSON 响应文档上点击则可将当前原文导入同一个标签页。默认自动接收浏览器允许访问的 HTTP/HTTPS JSON 响应，可在通用设置中随时关闭。

完整打包、安装和更新步骤见 [打包与安装说明](./打包与安装说明.md)。与原网站源码的逐文件对照见 [源码对照说明](./源码对照说明.md)。

## 安装已构建的插件

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目的 `dist` 目录。
4. 将「JSON 工具箱」固定到工具栏，点击图标打开工具。

如果使用发布 ZIP，请先解压，再选择包含 `manifest.json` 的目录。`dist/index.html` 由浏览器插件加载，不需要启动博客服务。

## 保留的功能

- JSON / JSON5 格式化、压缩、语法检查、转义与去转义。
- 可选 JSON 修复：兼容解析失败后在 Worker 中修复，可在新标签页查看原始数据与修复结果的只读 Diff。
- 长整数和高精度数值的字面量保留。
- JSON 排序、字段排序、数据脱敏与 Diff 对比。
- YAML、TOML、XML、Go、TypeScript 和 Cookie 转换。
- 本地文件导入、拖放、复制、结果下载。
- 插件专属 JSON 响应接收：默认开启，全 HTTP/HTTPS 站点在安装/升级时由浏览器统一确认访问；通用设置中可关闭，也支持点击图标主动导入当前 JSON 文档。
- 本地存档、设置、明暗主题、中英文切换、大文件折叠和层级分析。

## 已移除的功能和依赖

URL 获取、cURL、客户端证书请求、分享、我的分享和问题反馈已从入口、弹窗、设置和处理代码中移除。原博客的全屏／退出全屏按钮、默认全屏设置及相关状态和样式也已删除；普通编辑和 Diff 均直接使用整个工具标签页。项目不包含博客页面、SEO、Nuxt、Nitro、服务端 API、指纹采集或 WASM 分享鉴权。

编辑器和所有脚本随插件提供，数据处理不依赖后端。JSON 响应接收默认开启；网站访问在安装/升级时按浏览器规则统一确认，插件仅在浏览器允许的 HTTP/HTTPS 范围运行轻量探测，只接收顶层 JSON 文档。主动点击图标可通过 activeTab 临时读取当前 JSON 页面。不会监控所有 fetch/XHR，不读取浏览历史或浏览器 Cookie，也不会再次请求接口或上传正文；内容安全策略的 connect-src 仍限于插件自身。

设置与存档沿用原工具的 localStorage / IndexedDB 实现，按工具标签页管理。插件与原网站的存储空间相互独立，原网站中的数据不会自动迁入；需要手动导出并导入。卸载插件会清除其本地数据。

## 本地开发

需要 Node.js 20.19+ 或 22.12+，建议使用当前 Node.js LTS。

```sh
npm ci --include=dev
npm run dev
```

`dev` 提供前端开发页面和热更新。开发服务器地址会显示在终端中。要验证真实扩展环境，请构建后加载 `dist`；每次重新构建后，在浏览器扩展管理页面点击「重新加载」，再刷新工具标签页。

```sh
npm run typecheck
npm test
npm run build
npm run package
npm run verify-package
```

`build` 依次进行类型检查、生产构建和本地模式检查。`package` 生成 `release/json-tool-extension-1.1.5.zip`，可用于分发或提交扩展商店；商店上架资料见 [商店发布资料](./store/商店发布资料.md)。每次打包会生成源码指纹与 ZIP 校验记录，上传前用 `npm run verify-package` 确认安装包对应当前源码。

## 编辑器报错排查

首次打开源码前，先在项目根目录安装完整依赖：

```sh
npm ci --include=dev
npm run typecheck
```

`node_modules/` 不随源码提交。仅有该目录并不代表安装成功；如果提示找不到 Vue、Element Plus、Vite、TypeScript 或 `vue-tsc`，需要等 `npm ci` 成功结束后再检查。被中断的安装可能留下空目录，重新执行上述命令即可恢复。

本项目的 `tsconfig.json` 同时检查 Vue/TypeScript 源码、`vite.config.ts` 和 Monaco 构建脚本。构建脚本沿用原网站中的 JSDoc 类型，Node 类型由 `@types/node` 提供。

如果命令行类型检查通过而 TRAE 仍显示旧错误，执行「TypeScript: Restart TS Server」或「Vue: Restart Vue Server」，再重新打开报错文件。编辑 `.vue` 文件需要启用 Vue (Official) 扩展。

## 项目结构

```text
public/
  manifest.json             扩展配置与内容安全策略
  background.js             点击图标打开工具标签页
  icons/                    插件图标
src/
  App.vue                   独立入口和语言状态
  components/              编辑器、弹窗、本地处理逻辑与 Worker
  utils/jsonToolMessage.ts  消息提示
scripts/
  vite/monaco-large-folding.mjs  原工具的大文件折叠补丁
  check-local-only.mjs           在线依赖与扩展权限检查
  package.mjs                   发布打包
tests/                     核心功能、修复、折叠、编辑性能和设置迁移回归测试
```

当前编辑器沿用双栏桌面布局。浏览器窗口宽度低于 901px 时会显示大屏使用提示；侧边栏或手机布局需要另行适配。

本项目已从博客源码中独立抽取。后续可以作为新仓库维护；更新 JSON 工具时只需维护这个前端项目。

## 版本约定

版本号采用三段 `主版本.次版本.修订版本`：不兼容的大调整递增主版本，兼容的新功能递增次版本，修复和细节调整递增修订版本。这是项目约定；Chrome 扩展允许一到四段数字，详见 [Manifest 版本规则](https://developer.chrome.com/docs/extensions/reference/manifest/version)。

2026-10-10 新增 JSON 修复等功能，对应 `1.1.0`；2026-10-11 的 Go 转换、解码文案和折叠控件修复，对应 `1.1.1`。新的发布内容使用新的版本号，同时保留旧版 ZIP、构建记录和校验文件；不能只修改 ZIP 文件名，包内 Manifest 和项目版本号也必须一致。

## JSON 响应接收（1.1.5）

1. 加载最新 `dist` 后，浏览器按安装/升级权限规则统一确认 HTTP/HTTPS 网站访问，无需逐个输入域名。
2. 新安装默认自动接收 JSON 响应；开关位于“设置 → 通用设置”，在缩略图左边，缩略图仍为最后一项。此前明确关闭过的用户保留关闭偏好。
3. 在 Network 中双击 GET 请求，或直接访问接口地址；新页面返回明确的 JSON MIME 时，在本地 Worker 中按当前缩进、数组排版与编码设置格式化，再进入同一个标签页的编辑区。普通网页和 text/plain 不自动接管。
4. 关闭通用设置中的开关会停止自动探测，不撤销安装权限，也不影响本地编辑。自动关闭时仍可在 JSON 响应页面主动点击扩展图标导入。

自动导入上限为 20 MiB（按 UTF-8 字节计算），并行待处理最多 4 份、总预留上限 80 MiB；更大响应保留在原页，保存文件后可使用原有文件导入。响应提取与临时传输保持原文；载入前使用工具现有的数字保真格式化引擎，保留长整数、负零和小数末尾零。格式化不会自动启动容错修复；失败、超时或预计结果过大时，提示并导入原文。等待期间用户编辑、清空或更换输入模型会取消导入，避免覆盖修改。读完且编辑器确认载入后清理临时正文；记录有效期为 30 分钟，过期数据在后续使用或后台同步时清理。

“返回响应页面”会重新打开来源地址，返回结果可能变化；离开前需保存编辑。此功能读取新页面实际获得的响应，不保证它与先前 Network 请求完全相同。

权限仅为 storage、scripting、activeTab，加 HTTP/HTTPS 的 host_permissions；没有可选逐站点授权、静态 content_scripts、Cookie/历史/调试权限或服务器连接。浏览器内部页面、商店受限页面、file URL 和未授权的隐身窗口仍按浏览器限制处理。构建检查精确核对这组能力，继续禁止博客 API 和远程上传。


## 本地评价邀请（1.1.5）

评价邀请采用不遮挡编辑器、不抢焦点的非模态卡片。首次本地记录已满 7 天、累计至少 10 次有效使用且跨 3 个使用日后，才有机会展示。旧用户没有历史安装时间记录，从这版首次记录开始计时；扩展更新不会重置已有记录。

有效使用包括成功的格式化、压缩、去除转义、压缩并转义、格式转换，以及在当前可见且聚焦页面中成功格式化的 JSON 响应导入；失败操作、复制、清空和未检测到转义的处理不计入。所有扩展标签页共用计数，每 60 秒最多累计一次，连续快速点击不会增加次数。

达到条件后，在一次成功处理至少 10 秒且用户至少 5 秒没有输入、点击或滚动时才展示。页面必须可见且聚焦，并避开处理中、Diff、设置、其他弹窗、菜单和查找等交互；用户继续输入、点击或滚动会推迟展示；切换页面或打开弹窗会收起已展示的邀请。

- “去评价”仅在主动点击后新开 Chrome 应用商店的评价页面，并停止后续邀请。插件只能记录点击行为，不能判断用户是否实际提交了评价。
- “稍后再说”和右上角关闭按钮会将下一次邀请延后至少 30 天；每个本地浏览器资料最多展示两次。
- “不再提示”永久停止邀请；不会影响工具功能。

首次记录日期、有效使用次数和使用日期、展示次数、冷却时间及选择均保存在 `chrome.storage.local`，不记录处理内容、字段、来源地址或文件名，也不上传。清除扩展数据或重新安装后，本地记录可能重新开始。存储或消息通信失败时不展示邀请，不阻塞编辑和处理。
