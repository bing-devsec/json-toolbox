## 首次上传的操作顺序

1. 在项目根目录运行 `npm run verify-package`。如果失败，先运行 `npm run package` 再验证。
2. 在开发者后台的“内容”页点击“上传新内容”，选择 `release/json-tool-extension-1.0.0.zip`。输出目录中提供了同一份安装包副本。
3. 完成下列商店资料、隐私权实践和分发设置，上传 `assets/` 内图片。
4. 将 `privacy-policy.html` 放到可公开访问、无需登录的 HTTPS 页面，确认实际 URL 能正常打开，再填进后台隐私政策字段。请以实际部署和打开结果为准。
5. 确认账号的邮箱验证、两步验证与 Trader／Non-Trader 声明已完成，且符合实际情况。
6. 首次发布建议选择“审核通过后手动发布”，核对资料后再正式发布。

## 详细介绍：可直接复制

```text
JSON 工具箱，在浏览器里编辑、修复与核对数据。

为接口调试、配置检查、日志整理和测试数据处理提供一个独立工作区。点击扩展图标，粘贴文本、上传或拖入文件，即可在双栏编辑器中查看原始内容与处理结果。免费、无需注册，断网也能使用。

• 格式化、压缩与语法检查
把紧凑的数据整理为清晰的层级结构，或压缩为便于复制的文本。兼容带注释、单引号、尾逗号等常见 JSON5 输入，可调整缩进与简单数组的排版。开启语法校验后，错误会以红色波浪线提示，并可逐处定位。

• JSON 修复与结果核对
在设置中开启修复后，点击“格式化”，工具会在兼容解析失败时尝试修复常见的缺失逗号、引号、括号，以及部分嵌套 JSON 字符串的转义问题。修复完成后，可查看原始内容与修复结果的差异，核对字段、字符串和层级是否符合预期。

• 保留数字的原始细节
格式化与压缩时保留长整数、高精度小数、末尾零和指数写法。订单号、雪花 ID、金额与精确数值可以按原始文本核对，减少数字被舍入或改写带来的困扰。

• 层级折叠与结构浏览
可以按指定层级折叠数据，也可以单独展开对象和数组。折叠后显示对象键数或数组元素数，快速了解各部分的数据规模。面对嵌套较深或内容较多的文件，先查看整体结构，再展开需要检查的部分。

• 双栏差异对比
将两份内容并排比较，以行级和行内高亮显示新增、删除与修改。通过“上一处”和“下一处”定位差异，配合同步滚动核对上下文。适合检查接口响应变化、配置修改，以及修复前后的数据。

• 排序、去重与文本整理
按字段名、字段名长度或指定字段值排序，可配置处理范围与排序方向。右键菜单还提供数组排序、数组去重、按字段名提取值，以及文本行与数组之间的转换。清理空行、每行首尾空格，或批量添加、移除前后缀，便于整理日志片段和测试列表。

• 转义与编解码
支持压缩并转义，以及仅去除外层或递归去除多层转义，便于查看字符串中嵌套的数据。格式化设置可选择解码字符串里的 \uXXXX 和 \xHH 转义序列。选中字符串后，可通过右键执行 Base64 或 URL 编码、解码。

• 格式转换与类型生成
将数据转换为配置文件或标记格式，便于在其他工具中继续使用；也可从输入样本生成 Go 结构体和 TypeScript 类型定义。Go 转换会结合嵌套对象、数组元素与数值特征推断类型，识别重复结构，并处理样本中的缺失与空值字段，为编写数据模型提供起点。还支持将手动粘贴的 Cookie 文本转换为键值数据。

• 快速取值与局部操作
双击选中完整字符串，在预览区双击还可自动复制。右键复制字段路径，或对选中的内容执行适用的整理与编解码操作。配合查找、替换、自动换行和常用编辑快捷键，减少反复选取与复制。

• 字段脱敏与本地存档
按字段路径或数组通配符指定处理范围，可删除字段、替换为固定值或 null，也可保留部分字符并遮盖其余内容，便于准备调试示例。编辑区内容可保存为当前工具标签页的本地存档，方便切换、更新、重命名或删除；处理结果可复制或下载。

• 按习惯调整工作区
支持明暗主题、中英文切换、字号调整与同步滚动。编辑区和预览区之间可以拖动分隔线调整宽度，并将处理结果转移回编辑区，继续修改。

这套工作区围绕“看清内容、处理数据、核对结果”来设计。原始输入与处理结果放在两侧，方便随时比较；是否将结果写回编辑区，由你决定。常用功能放在工具栏，针对选中内容的操作放在右键菜单，进一步的行为通过设置调整。

数据的细节应当可见。数字保留原始写法，折叠结构显示规模，修复提供差异核对，让你能够判断工具做了什么，以及结果是否符合自己的意图。

本地处理是整个工具的基础。编辑器和处理功能随扩展提供，输入内容、文件和存档不上传到开发者或第三方；JSON 响应接收默认开启；仅在浏览器允许访问的 HTTP/HTTPS 范围读取 JSON 文档，可在通用设置中关闭，不读取浏览历史或浏览器 Cookie。设置与存档保存在本机，无广告、无需账号，重要内容可通过下载自行备份。
```

## 如何确认安装包是最新的

`npm run package` 先构建当前源码，再生成 ZIP。ZIP 内的 `build-info.json` 记录 UTC 构建时间、Git 提交、是否含未提交修改及运行源码指纹；`release/` 同时生成 `.build-info.json` 与 `.zip.sha256`。

`npm run verify-package` 会核对当前版本与名称、源码和锁定文件的 SHA-256，以及 ZIP 的完整性。源码变更或 ZIP 被替换后会失败。文档与商店图片不影响运行，不纳入源码指纹。校验值用于核对本地构建，不代替 Google 的扩展签名。

上传前不要只靠 `1.0.0` 文件名或修改时间判断。以后重新构建后，请从项目 `release/` 取最新 ZIP；本次输出目录中的副本是本次交付时的快照。
